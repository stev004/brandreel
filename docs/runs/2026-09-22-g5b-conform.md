# G5b conform - 2026-09-22

Luna xhigh implemented the standalone conform stage. Parent reviewed source discovery, symlink boundaries, frame rate and duration handling, RIFE invocation and fallback, and staged output replacement.

## Behavior

Video inputs under assets are converted to square-pixel 1080x1920 H.264 at 60fps. Default crop fills the frame; optional pad preserves the full input. Source audio is retained as AAC. Output mapping is `assets/conformed/manifest.json`, version 1, with source/file relative paths, input/output probe facts, interpolation method and fit mode.

Practical-RIFE 4.25 is used only when its configured checkout, model and Python can run. Its integer multiplier produces an intermediate rate at least 60fps; ffmpeg then conforms that rate without intentionally changing speed. Wrong RIFE rate/duration or inference failure warns and falls back to ffmpeg minterpolate. The local machine has no usable RIFE installation, so actual model quality is not claimed. Invocation and failures are covered with injected runners. [Upstream CLI reference](https://github.com/hzwer/Practical-RIFE).

Padding precedes interpolation so short clips and the source tail remain represented; trimming selects the planned frame count. Final output dimensions, sample aspect ratio, exact frame rate, duration and frame count are probed before publication. All clips stage before replacement; this is not a transactional filesystem across multiple final files if a late rename fails.
