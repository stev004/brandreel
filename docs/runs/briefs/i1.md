Design:
1. bin/interview.mjs <workspace> [--answers <file.json>] [--brand <name>] [--defaults]: asks a fixed question set on the terminal (node:readline/promises; each question shows its default in brackets; Enter accepts the default) or takes them from --answers (non-interactive; --defaults fills unanswered questions with defaults so CI never blocks). Writes workspace/<id>/brief.json and prints it. Questions, in order, with keys: brand (default from --brand or the existing script.json), topic (required), audience (who is watching and the specific situation they are in; required), hookArchetype (one of curiosity-gap | contrarian-claim | direct-callout | numbered-promise; default direct-callout), hookLine (optional exact first line), coreMechanic (one sentence, the single visual idea; required), facts (list of numbers/claims the video MAY use, comma separated; default empty = no figure beat allowed), beatKinds (subset of moment,question,figure,verdict; default all four, figure removed automatically when facts is empty), targetDurationMs (default 25000, 15000-35000), voice (Kokoro voice id or "none"; default none), music (path or "none"; default none), platform (tiktok | reels | shorts; default reels), url (default none), tagline (default none), requiredPhrases (default empty), bannedPhrases (default empty), notes (free text, default empty). brief.json = { version: 1, ...answers, createdAt } with lists as arrays. Validation before writing: required keys present, enums valid, duration in range; exit 1 with a list on failure.
2. bin/script.mjs: if workspace/<id>/brief.json exists, it is loaded and (a) --topic becomes optional (brief.topic wins if --topic absent; if both, --topic overrides and a line is printed), (b) modules.vo / modules.music / close.url / close.tagline come from the brief unless the flag is given (flag overrides), (c) the prompt gets a BRIEF section rendered verbatim (audience, hook archetype, hook line, core mechanic, facts, allowed beat kinds, required and banned phrases, notes) with the rules: coreMechanic in the output must equal the brief's; the first beat must follow the hook archetype; every figure beat's value.to, axis numbers and goalText numbers must come from brief.facts; only allowed beat kinds; required phrases must appear somewhere on screen; banned phrases must not, (d) validation enforces: coreMechanic equals brief.coreMechanic (trim, case-insensitive), beat kinds subset of brief.beatKinds, every number appearing in a figure beat (value.to, axis.min/max/achieved/goal and any digits inside label/goalText/stamps) must appear as a number in brief.facts (parse numbers out of the fact strings), required phrases present, banned phrases absent, and if hookLine is set the first beat's first on-screen text (moment.line or question.lines[0] etc.) equals it. Without a brief, behaviour is unchanged.
3. bin/reel.mjs: an "interview" stage before manifest that runs only when brief.json AND script.json are both missing; it runs bin/interview.mjs (interactive) - in --dry-run it is listed as "interview: ..." under the same condition. A "script" stage after interview runs bin/script.mjs when script.json is missing (uses the brief; needs --model-cmd passthrough: add --model-cmd to reel, default claude -p). Existing behaviour when script.json exists is unchanged.
